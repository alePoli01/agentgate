## 1. The Mandatory Markdown Task Schema

> [!IMPORTANT]
> **Human-Readable & Machine-Strict Task Structure**
> All planning workflows (`/plan`, `/refine`) MUST output task definitions using the **Markdown Planning Schema** below. Do NOT use raw XML `<task>` tags — plans must render natively as clean Markdown for easy human inspection and discussion. During `/execute`, the agent outputs the **Execution Audit & Evidence Block** *after* writing and testing the code.

### Planning Schema (written by `/plan` and `/refine` into `*-PLAN.md`)
```markdown
## Task T-01: Clear descriptive name
| Skill | Effort | Type | Depends On | Priority |
|---|---|---|---|---|
| `/execute` | `low` \| `medium` \| `high` | `auto` \| `manual` | `—` or `T-xx` | `high` \| `normal` \| `low` |

**Files:** `exact/path/to/file1.ts`, `exact/path/to/file2.ts`

### Action
1. Specific, step-by-step implementation instructions.
2. Strictly honor `.ai/DECISIONS.md` and user-specified constraints.

### Verification
- **Verify Command:** `executable command that proves completion`
- **Done Criteria:** Measurable acceptance criteria.

### Checkpoint
- [ ] Update `.ai/DECISIONS.md` if an architectural decision was made (or state `NO_DECISION — [summary]`)
- [ ] Update `.ai/STATE.md` Current Position to reflect this task is done
- [ ] Update `.ai/MEMORY.md` to clear this task from Active TODOs
- [ ] Run: `git add -A && git commit -m "checkpoint: [task name]"`
```

### Execution Audit & Evidence Block (generated by `/execute` AFTER code is written)
```markdown
### Self-Critique (4-Point Audit)
1. **Comment vs. Code Check:** [Confirm all docstring/comment logic is actually implemented in code]
2. **Constants & Cache Check:** [Confirm user-specified intervals/limits and cache rules are honored]
3. **External API Safety:** [Confirm any scheduled/looping calls have active guards and TTL caching]
4. **Modularity Check:** [Confirm code is split by layer (core-rules §11); new files <300 lines; no unrequested monolith refactors]

### Evidence
```text
[raw stdout/stderr from terminal | MANUAL_VERIFICATION_REQUIRED]
```
```

## 2. Section Definitions (Planning vs. Execution)

### Written at Planning Time:
- **Metadata Table**:
  - `Skill`: The AgentGate skill to use when executing this task (`/execute`, `/debug`, `/verify`, `/refactor`, `/test`, `/review`, `/security`). When the agent picks up this task, it MUST read and follow the corresponding `skills/<skill>/SKILL.md` file.
  - `Effort`: `low` (simple edits), `medium` (multi-file or logical changes), `high` (architectural refactor).
  - `Type`: `auto` for tasks the agent can do itself, `manual` for tasks requiring user action.
  - `Depends On`: `—` or the Task ID that must be COMPLETE before this task can start.
  - `Priority`: `high`, `normal`, or `low`.
- **`**Files:**`**: Comma-separated list of exact file paths this task targets.
- **`### Action`**: Numbered, step-by-step instructions of what to build or change. Must strictly honor `.ai/DECISIONS.md` and user-specified constraints without inventing unrequested behaviors.
- **`### Verification`**:
  - `Verify Command`: The exact terminal command (e.g., `npm run build`, `pytest`, `curl`) the agent will run to prove the code works.
  - `Done Criteria`: Measurable conditions that define completion.
- **`### Checkpoint`**: **MANDATORY for all tasks.** Checkboxes listing the lifecycle maintenance steps the agent must complete before marking this task COMPLETE.

### Populated Only at Execution Time (NEVER pre-filled in a plan):
- **`### Self-Critique (4-Point Audit)`**: **MANDATORY for Medium/High effort tasks.** Evaluated *after* the code is written, auditing the actual diff against comments, user constants, caching rules, and modularity/separation of concerns before running `Verify Command`.
- **`### Evidence`**: The literal terminal output captured *after* running `Verify Command`. Pre-filling `Evidence` during planning is a protocol violation.

## 3. The Evidence Gate Requirement

> [!CAUTION]
> **No "Trust Me" Approvals.**

You are strictly forbidden from placing conversational filler (e.g., "The code is complete and looks correct", "pytest output showing all tests passing") inside the `### Evidence` block.
The `### Evidence` block MUST contain:
1. The raw `stdout`/`stderr` from the terminal (e.g., test results, compiler output).
2. Or, if the task is purely visual or un-testable via terminal, the exact string: `MANUAL_VERIFICATION_REQUIRED`.

If an agent outputs a task completion without empirical evidence, it immediately fails the Evidence Gate.

---

## 4. The Checkpoint Requirement

An agent MUST NOT mark a task COMPLETE if the `### Checkpoint` steps have not been executed:
1. A `.ai/DECISIONS.md` entry (or explicit `NO_DECISION` statement)
2. A `.ai/STATE.md` update
3. A `.ai/MEMORY.md` update
4. A `git commit`
